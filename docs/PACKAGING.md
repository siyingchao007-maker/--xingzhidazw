# 打包范围与数据边界

该仓库由白名单重新组装，不复制原知识库后再逐项删数据。正式知识库、旧源码目录和历次补丁保持不变。

## 纳入

当前插件内部模块、全部独立 CJS 配套模块、CSS、PNG 界面资产、插件清单、能力定义与注册表、系统模板与契约、可移植离线测试、新的独立构建脚本。

`export-inventory.json` 记录初始导入文件的来源类别、长度与 SHA-256，不包含电脑绝对路径。能力正文和历史规范作为定义保留，不代表每项能力都默认启用或每项设计已通过真实运行验收。

## 排除

个人记忆和历史资料目录、真实会话、知识条目、行动与结果、`data.json` 及备份、`state-store/`、运行工作区、检索索引、`.codex/`、Obsidian 工作区状态、真实许可证、`capabilities.xcap`、密钥和令牌、旧 Git 历史、调试截图、临时导出、既有安装/回滚工具中的个人路径。

项目方法、通用模板与能力文档可能使用行业示例；不应把所有能力文件自动视作完全无私人内容。上传前需扫描，并保留真实的验证边界。

## 后续安全规则

保持仓库私有。每次提交前检查暂存文件，不要只依赖 `.gitignore`；被跟踪文件及历史版本不会因为添加忽略规则而自动消失。任何真实密钥若误传，应先撤销或轮换，再处理历史。不要通过削弱运行授权机制使干净安装包看起来已获授权。
