# Judgment Kernel V3 使用说明

版本：3.0.0  
适用插件：行知 0.45.0

## 1. 作用

Judgment Kernel V3 将复杂选择整理为可审查的 Decision Record，并区分模型候选、用户决定、系统派生状态、验证行动和现实反馈。它不替用户决定，也不因为模型建议、证据过期或一次行动失败而改写已确认判断。

## 2. 从对话到现实反馈

1. 用户主动运行“从当前对话生成判断候选 V3”。
2. 插件读取可见对话、实际路由透镜轨迹和对话内持久化的在线来源目录；模型只返回候选信封。
3. 程序拒绝越权字段、伪造透镜、无来源消息和不在真实证据目录中的证据引用。
4. 用户先看完整候选预览；保存只建立待审查记录。
5. 用户在判断卡写下自己的理由并明确确认，系统才生成不可变快照。
6. 行动绑定到特定快照和特定选项、主张或假设。
7. 反馈绑定到精确行动与快照，并只生成单独的复审候选。

不保存或展示隐藏思维链。PATH 真实运行轨迹来自可见 `capabilityTrace`；没有实际路由轨迹时不伪造透镜来源。

## 3. 命令

在 Obsidian 命令面板搜索“Judgment Kernel V3”：

- 从当前对话生成判断候选 V3
- 手动新建判断记录 V3
- 打开当前判断卡 V3
- 审查当前判断证据 V3
- 为当前判断创建验证行动 V3
- 为当前判断行动记录反馈 V3
- 只读打开当前认知循环 V2
- 设置 Judgment Kernel V3 功能开关
- 查看 Judgment Kernel V3 运行指标
- 运行 Judgment Kernel V3 完整自检

## 4. 功能开关

| 开关 | 关闭后的行为 |
|---|---|
| 候选生成 | 不调用当前对话模型生成候选 |
| 持久化 | 允许预览和校验，但不保存判断、快照、行动或反馈 |
| 已有记录只读 | 可以打开和检查；不允许修改、确认、证据审查、追加行动或反馈 |
| 影子模式 | 允许生成并校验候选、记录安全指标，但不写正式判断数据 |

前三个开关相互独立。设置保存于 `00_系统/判断内核/V3运行设置.json`。影子模式下仍会写入无正文的运行指标文件。

## 5. 数据位置

| 数据 | 位置 |
|---|---|
| Decision Record | `06_判断与决策/决策记录/` |
| 不可变快照 | `06_判断与决策/决策记录/_快照/` |
| 复审候选 | `06_判断与决策/决策记录/_复审候选/` |
| 验证行动 | `07_行动/判断验证/` |
| 反馈观察 | `08_结果与反馈/判断反馈/` |
| 设置与指标 | `00_系统/判断内核/` |

记录采用“人可读 Markdown + 权威 JSON 数据块”。更改现有记录使用 Obsidian `Vault.process` 和修订号比较；并发冲突时操作停止。快照先创建，主记录提交失败时按引用检查进行补偿删除。

## 6. 证据和反馈规则

- 证据状态为 `retrieved → used → cited → user-confirmed`，只允许向前推进。
- 外部证据候选来自当前对话内真实保存的在线证据目录。模型不能提供自己的 URL、检索时间或新鲜度覆盖目录值。
- `user-confirmed` 只能由用户在证据审查界面逐条确认。
- 行动验证目标必须存在于绑定快照。假设必须来自 `hypothesis` 主张，反馈目标保留 option/claim/assumption 类型。
- 反馈只创建复审候选，不自动修改当前 Decision Record 或不可变快照。

## 7. V2 旧记录

`cognitiveSchemaVersion: 2` 使用旧内嵌认知循环标记只读检测。只读命令展示标题、判断、快照数和行动绑定情况，不转换、不保存、不重写旧文件。

- PATH 运行时 1.5.0：保留母概念 V0.6 和观境、立心、践真、知变完整呈现，新增候选交接边界。
